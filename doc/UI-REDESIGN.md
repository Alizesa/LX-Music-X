# Android UI 重构说明

## 页面结构

### 首页

从上到下排列：

1. 状态栏与“推荐”标题。
2. 右上角菜单入口。
3. 圆角搜索框，点击进入现有全局搜索。
4. 推荐 Banner，数据可来自 QQ 音乐推荐或默认推荐。
5. 快捷入口：猜你喜欢、每日推荐、排行榜、分类歌单、新歌新碟。
6. 推荐歌曲列表，支持点击播放和进入歌曲操作菜单。
7. 推荐歌单横向列表，支持进入现有歌单详情页。
8. 底部悬浮播放条。
9. 底部 Tab：首页、我的。

### 我的

从上到下排列：

1. “我的”标题和右上角菜单。
2. 搜索入口。
3. 用户资料卡；未登录时显示默认头像和登录入口。
4. 账号相关入口，仅作为信息入口，不新增付费业务。
5. 统计入口：试听列表、我的收藏、本地音乐、下载管理。
   - 前三项的数量直接读本地列表，是真实值；下载管理只作为入口，不给数字。
   - 原计划的“最近播放”在本项目里没有对应实现，用实际存在的试听列表替代。
6. 自建歌单、收藏歌单（按 `subscribed` 区分）和外部歌单导入。
7. 设置、同步、音源管理等原有功能入口（收在右上角“更多”面板里）。
8. 底部悬浮播放条和底部 Tab。

## 视觉约束

- 背景使用浅灰或主题背景，正文使用高对比度黑色。
- 主强调色使用绿色，按钮和激活 Tab 统一使用主题色变量。
- 卡片圆角、图片圆角和间距保持统一，避免嵌套卡片。
- 列表项必须保留加载、空状态和错误状态。
- 所有内容区域为可滚动布局，并为底部播放条预留安全间距。
- 使用现有 `Icon`、`Text`、`Image`、主题和缩放工具，不重复造基础组件。

## 导航迁移

现有 `nav_search`、`nav_songlist`、`nav_top`、`nav_love`、`nav_qq`、`nav_download`、`nav_setting` 等能力不删除。它们改为由首页快捷入口、我的页面和右上角“更多”面板触达。侧边栏组件不再挂载到 Android 竖屏首页；横屏和其他平台暂不调整。

约束：

- `DrawerNav` 已不再被引用（文件保留），`Header` 的菜单按钮也不再发 `changeMenuVisible`，它由 `Main` 注入的 `onMenuPress` 打开“更多”面板。
- 底部 Tab 由 `Vertical` 渲染，位于播放条**下方**，并且在任何 `mode`（含旧功能页）下都显示 —— 这是从旧功能页回到仪表盘的唯一入口，不能只在仪表盘里渲染。
- `navActiveId` 仍是页面状态的唯一来源：进旧功能页必须走 `Main` 的 `openLegacy`（同时 `setNavActiveId` 和 `setMode`）。
- 旧功能页的标题栏菜单、以及两个仪表盘的右上角菜单，都指向同一个“更多”面板，不要各自实现。

## 组件职责建议

- 页面组件只负责布局、交互和展示状态。
- 推荐数据通过独立 hook 或适配函数获取，不在 JSX 中拼接 QQ 请求。
- 播放、歌单详情、搜索和下载继续调用现有导航及事件系统。
- UI 改造不改变 `MusicInfo`、歌单和播放器状态的公共数据结构。
